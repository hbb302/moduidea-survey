   v2 핵심 변경 사항 (응답률 향상 목적 · 황변리사님 의견 반영)
────────────────────────────────────────────────────────────────

   1)  정책/기술 분리 발송 구조로 변경
       └  같은 HTML 파일에 URL 파라미터로 분야 결정

            정책 분야  ?type=policy
            파라미터 없으면 게이트 화면(접근 경로 안내) 표시

   2)  아이디어 ID(접수번호) 항목 삭제
       └  '접수번호 확인' 문의 차단 목적

   3)  '아이디어 제안 부문' 선택 항목 삭제
       └  URL이 분야를 결정하므로 응답자가 직접 선택 불필요

   4)  워크숍 불참 사유 입력란 삭제
       └  참석/불참 라디오만 유지

   5)  이해도 5점 척도 → 3점 척도로 단순화
       └  '그렇지 않다 / 보통이다 / 그렇다'
       └  안내문 추가: "본 문항은 사전 참고용 간단한 체크 항목입니다.
                       오래 고민하지 마시고 현재 상태를 편하게 표시해 주시면 됩니다."

   6)  '고도화 사업 운영 원칙' 섹션 통째 삭제
       └  해당 내용은 워크숍 당일 서약서 형태로 별도 진행
       └  매뉴얼·고도화 안내 자료에 반영 (사전 설문 부담 제거)

   7)  검증 방법 입력 방식 변경
       └  주관식 textarea → 체크박스 카드 (복수 선택)
       └  매뉴얼 예시 그대로 옵션화 (기술 6개 / 정책 8개)
       └  '기타' 선택 시 직접 입력란 자동 노출

   결과:  9문항 → 5문항으로 축소  ·  소요 시간 10분 → 약 5분

────────────────────────────────────────────────────────────────
   0단계 · 미리보기 (배포 전 디자인 확인)
────────────────────────────────────────────────────────────────

index.html 파일을 더블클릭 → 브라우저로 열면 게이트 화면이 표시됩니다.
주소창 끝에 다음 중 하나를 붙여 새로고침해 보세요.

      ?type=tech       → 기술 분야 설문 화면
      ?type=policy     → 정책 분야 설문 화면

   ─ 디자인이 키비주얼 톤과 맞는지
   ─ 모바일·태블릿에서도 보기 좋은지 (브라우저 창 폭을 줄여보세요)
   ─ 분야 배지가 헤더에 노출되는지
   ─ 3점 척도 / 체크박스 카드 클릭이 부드러운지

이 단계에서는 제출을 눌러도 백엔드가 연결되지 않아 응답이 저장되지
않습니다. (콘솔에 "백엔드 미연결" 안내가 표시됩니다.)


────────────────────────────────────────────────────────────────
   1단계 · 응답 저장용 Google 스프레드시트 만들기
────────────────────────────────────────────────────────────────

1)  Google 드라이브 (https://drive.google.com) 접속
2)  '새로 만들기' → 'Google 스프레드시트' → '빈 스프레드시트'
3)  파일명 변경
       예) [2026 TOP100 Summit] 사전설문 응답
4)  주소창 URL에서 스프레드시트 ID 복사
       https://docs.google.com/spreadsheets/d/  ←여기 ───  /edit
                                              [ 이 부분이 ID ]
       예) 1AbCdEfGhIjKlMnOpQrStUvWxYz0123456789

   ※ 시트 탭은 그대로 두어도 됩니다. 첫 응답이 들어오면 '응답' 탭에 헤더가
     자동으로 만들어집니다.


────────────────────────────────────────────────────────────────
   2단계 · Apps Script 백엔드 배포
────────────────────────────────────────────────────────────────

1)  https://script.google.com 접속 → '새 프로젝트'
2)  프로젝트 이름 변경
       예) 모두의아이디어_설문_API_v2
3)  좌측 코드 편집기 기본 코드를 모두 지움
4)  apps_script_backend.gs 파일 전체 내용을 복사하여 붙여넣기
5)  상단 SHEET_ID 값을 1단계에서 복사한 ID로 교체
       const SHEET_ID = '1AbCdEfG...........';
6)  관리자 알림 메일을 받고 싶다면 ADMIN_EMAIL 값도 입력
       const ADMIN_EMAIL = 'gpt@rnbdp.com';      ← 비우면 알림 없음
7)  Ctrl+S 로 저장

8)  좌측 함수 선택창에서 runSetup → ▶ 실행
       처음 실행 시 권한 동의 화면이 뜸 →
       '계속 진행' → 본인 Google 계정 선택 →
       '안전하지 않음(이동)' → '허용'
       → 콘솔에 "Setup OK ─ 시트: 응답, 행: 1" 이 나오면 성공
       → 스프레드시트로 돌아가면 '응답' 탭이 생기고 헤더가 채워져 있음

9)  배포 → 새 배포
       설정 ⚙ : '웹 앱(Web app)' 선택
       설명     : v2
       다음 사용자로 실행 : 나 (본인 계정)
       액세스 권한       : 모든 사용자 (Anyone)
       → '배포' 클릭
       → '웹 앱 URL' 표시됨 → 복사

   ※ '액세스 권한: 모든 사용자' 가 핵심입니다.
     응답자가 로그인 없이 제출할 수 있어야 합니다.

   ※ 기존 v1 배포가 있으면 별도 배포로 추가해도 되고,
     기존 배포의 새 버전으로 업데이트해도 됩니다. (배포 → 배포 관리 → ✏)
     ─ 새 버전으로 업데이트하면 기존 URL 그대로 사용 가능


────────────────────────────────────────────────────────────────
   3단계 · index.html 에 URL 연결
────────────────────────────────────────────────────────────────

1)  index.html 을 메모장 (또는 VS Code 등) 으로 열기
2)  Ctrl+F 로 다음 줄 찾기
       const APPS_SCRIPT_ENDPOINT = "__APPS_SCRIPT_URL__";
3)  __APPS_SCRIPT_URL__ 부분을 2단계에서 복사한 URL로 교체
       const APPS_SCRIPT_ENDPOINT = "https://script.google.com/macros/s/AKfy.../exec";
4)  저장

   ※ 따옴표 안 글자만 교체하세요.


────────────────────────────────────────────────────────────────
   4단계 · HTML 호스팅 (셋 중 하나 선택)
────────────────────────────────────────────────────────────────

옵션 A · 가장 빠른 방법 — Vercel 드래그앤드롭
   1) https://vercel.com 가입
   2) 대시보드 → 'Add New' → 'Project' → 'Browse'
      또는 메인 화면에 index.html 을 그대로 드래그
   3) 자동으로 https://[프로젝트명].vercel.app 도메인 발급

옵션 B · GitHub Pages
   1) GitHub 저장소 생성 (Public)
   2) index.html 업로드 (커밋)
   3) Settings → Pages → Source: main 브랜치 → Save
   4) https://[아이디].github.io/[저장소명]/index.html 활성화

옵션 C · 회사·기관 홈페이지에 게시
   1) 운영 담당자에게 index.html 파일 전달
   2) /survey/index.html 등의 경로에 업로드 요청

   ※ 어느 옵션이든 단일 파일(index.html) 만 올리면 됩니다.
     이미지·폰트는 모두 파일 안에 내장되어 있어 별도 첨부 불필요합니다.


────────────────────────────────────────────────────────────────
   5단계 · 분야별 단축 URL 두 개 만들기 (필수)
────────────────────────────────────────────────────────────────

호스팅 URL 끝에 ?type=tech 또는 ?type=policy 를 붙여 두 가지 링크를 만듭니다.

   기술 분야 원본
      https://moduidea-survey.vercel.app/?type=tech
   정책 분야 원본
      https://moduidea-survey.vercel.app/?type=policy

각각을 단축 URL로 변환하여 발송용으로 준비합니다.

   ─ 네이버 단축 URL    https://me2.do
   ─ Bitly              https://bitly.com
   ─ TinyURL            https://tinyurl.com

예시
   기술 분야  https://me2.do/abcTech
   정책 분야  https://me2.do/abcPolicy

발송 시
   ─ 기술 분야 40명에게는 '기술 단축 URL' 만 발송
   ─ 정책 분야 60명에게는 '정책 단축 URL' 만 발송
   ─ 잘못된 링크 접속 시 응답자는 '접근 경로를 확인해 주세요' 게이트 화면을 봄
     (응답 자체가 차단되어 분야 혼동 데이터가 시트에 쌓이지 않습니다)


────────────────────────────────────────────────────────────────
   배포 후 점검 체크리스트 (반드시 분야별 1회씩 직접 테스트)
────────────────────────────────────────────────────────────────

   □ 단축 URL 두 개 모두 정상 접속되는가
   □ PC / 모바일에서 모두 정상 표시되는가
   □ 파라미터 없이 접속 시 게이트 화면이 표시되는가
   □ 헤더 분야 배지가 정확히 표시되는가 (기술/정책)
   □ 4-1 체크박스가 분야별로 다르게 노출되는가 (기술 6개 / 정책 8개)
   □ '기타' 선택 시 입력란이 자동 노출되는가
   □ 동의 '동의하지 않음' 선택 시 안내 팝업이 뜨는가
   □ 필수 항목 누락 시 빨간 표시와 안내 배너가 뜨는가
   □ 정상 제출 시 '제출이 완료되었습니다' 팝업이 뜨는가
   □ 스프레드시트에 새 행이 추가되었는가 ('분야' 컬럼 값 확인)
   □ (옵션) 관리자 알림 메일이 도착했는가

테스트 응답은 시트에서 행 우클릭 → '삭제' 로 정리 가능합니다.


────────────────────────────────────────────────────────────────
   응답 시트 컬럼 구조 (v2)
────────────────────────────────────────────────────────────────

   A  번호
   B  제출일시(KST)
   C  분야                       ← 기술 분야 (Technology) / 정책 분야 (Policy)
   D  개인정보 동의
   E  성명
   F  연락처
   G  이메일
   H  참석 여부                  ← 참석 / 불참
   I  이해도 [전문성]            ← 그렇지 않다 / 보통이다 / 그렇다
   J  이해도 [보충자료]          ← 동일
   K  이해도 [의견수렴·실증]     ← 동일
   L  희망 검증 방법 (복수)      ← 콤마 구분 (예: "설계 검증, MVP·시작품 제작, 기타")
   M  검증 방법 (기타 직접 입력)
   N  지원 가능 부분 (주관식)
   O  UserAgent
   P  Language

활용 팁
   ─ C열을 '데이터 → 필터' 로 걸면 기술/정책 응답을 분리 분석 가능
   ─ L열 검증 방법은 COUNTIF / FILTER 로 항목별 선호도 집계 가능


────────────────────────────────────────────────────────────────
   할루시네이션·운영 리스크 차단을 위해 적용한 것들
────────────────────────────────────────────────────────────────

1)  설문 문항 문구는 docx 매뉴얼(사전설문지_TOP100Summit_260526_v3) 의
    원문 표현을 유지했으며, 4-1 체크박스 옵션은 매뉴얼에 기재된
    예시 6개(기술) / 8개(정책)를 그대로 옵션화했습니다.

2)  서버에서 한 번 더 필수값 + 형식 검증을 수행합니다.
    프론트엔드 검증을 우회하더라도 잘못된 데이터는 저장되지 않습니다.

3)  분야 값은 화이트리스트로 검증되어 변조된 type 파라미터가 들어와도
    저장이 거부됩니다.

4)  '기타' 선택 시 입력값 누락은 서버에서 거절합니다.

5)  개인정보 동의 '동의하지 않음' 응답은 서버에서 거절합니다.

6)  동시 제출 시에도 응답 번호가 꼬이지 않도록 ScriptLock 적용.

7)  연락처 셀은 텍스트 포맷으로 저장됩니다.
    (010-0000-0000 이 수식·날짜로 인식되는 사례 차단)

8)  설문 페이지에 외부 트래커·광고 스크립트가 일절 없습니다.
    Pretendard 웹폰트 CDN(jsDelivr) 만 외부 로드합니다.
